# Incident: Reception Desk Offline Local Cache Sync and Network Drop Recovery

## Purpose
Operational recovery procedure for branch-level network drops, reception desk offline token generation, local IndexedDB caching synchronization backlogs, and multi-branch queue desynchronization.

## Impact
- **Affected Services:** Branch OPD Front Desk registration, Token/Queue live display, Walk-in appointment booking during WAN outages.
- **Branch Experience:** Front desk staff switching to local offline browser cache; potential token number collision or delay in updating the central doctor queue once internet is restored.

## Symptoms
- Branch reception terminals show `🟡 Offline Mode Active / Local Cache Storage`.
- Token issuance API `/api/v1/appointments/queue/token` returns network timeout from branch desktop clients.
- Upon network reconnection, batch upload endpoint `POST /api/v1/appointments/sync/batch` experiences 409 conflict errors or latency spikes.
- Doctor consultation queue does not immediately show walk-in patients registered while the branch was offline.

## Severity
**P1 — Branch Operational Degradation During Network Outage**

## Immediate Actions
> [!IMPORTANT]
> **SAFE AUTOMATION vs REQUIRES HUMAN APPROVAL**
> - *Safe to automate:* Triggering local browser IndexedDB queue sync upon network reconnection; scaling central sync worker pods.
> - *Requires human approval:* Merging conflicting duplicate token numbers or reassigning consultation slots.

1. **Verify Branch Local Storage Integrity:** Ensure reception desktops keep local IndexedDB storage intact and do not clear browser cache or close active browser sessions.
2. **Engage Branch Token Prefix Isolation:** Ensure offline tokens generated by the branch use the dedicated branch offline prefix (e.g., `TK-BR01-OFF-101`) to avoid primary key collisions with central online appointments.

## Diagnosis
1. **Check Central Sync Ingestion Queue Depth:**
   ```bash
   redis-cli -u "$REDIS_URL" LLEN "bullmq:branch-sync:wait"
   redis-cli -u "$REDIS_URL" LLEN "bullmq:branch-sync:failed"
   ```

2. **Inspect Branch Sync Logs on Ingress Gateway:**
   ```bash
   tail -n 200 /var/log/nginx/access.log | grep "/api/v1/appointments/sync/batch"
   ```

3. **Check for Slot Assignment Conflicts in Database:**
   ```sql
   SELECT appointment_id, patient_id, doctor_id, branch_id, scheduled_at, token_number, status 
   FROM appointments 
   WHERE branch_id = '<BRANCH_UUID>' AND created_at >= NOW() - INTERVAL '2 hours'
   ORDER BY scheduled_at ASC;
   ```

## Recovery

### Scenario A: Network Restored — Batch Sync Backlog
1. Trigger automatic queue flush on the reception desk browser client:
   - Client executes sequential push of all cached `syncOutbox` records to `POST /api/v1/appointments/sync/batch`.
2. Ensure API Gateway processes branch transactions with idempotent upserts (`ON CONFLICT (appointment_id) DO UPDATE`).
3. Scale the BullMQ appointment sync worker:
   ```bash
   kubectl scale deployment bullmq-branch-sync-worker --replicas=8 -n hms-prod
   ```

### Scenario B: Token Collision / Slot Overlap Resolution
1. When an offline walk-in token collides with a pre-booked online slot:
   - Server applies **Priority Staggering**: The pre-booked online patient retains their reserved time window; the walk-in offline patient is automatically slotted into the next available immediate gap in the doctor's active queue.
2. Doctor's queue UI dynamically updates via WebSocket broadcast.

## Validation
1. Confirm all branch offline tokens have transitioned to `status: 'synced'`:
   ```sql
   SELECT COUNT(*) FROM appointments 
   WHERE branch_id = '<BRANCH_UUID>' AND status = 'pending_sync';
   ```
   *Expected count: 0.*
2. Confirm the doctor's live queue dashboard displays all waiting patients in correct sequence.
3. Scale worker pods back to normal:
   ```bash
   kubectl scale deployment bullmq-branch-sync-worker --replicas=3 -n hms-prod
   ```

## Rollback
- "No verified rollback mechanism found." (Synchronized appointments are committed to the clinical database; cancellations follow standard clinic workflow).

## Escalation
- **Escalate to:** Branch Operations Lead and Platform Frontend Lead.
- **Escalation Threshold:** Branch network drop exceeds 1 hour or > 20 unsynchronized patient tokens fail batch upload.

## Do Not
- **DO NOT** clear browser cookies, local storage, or IndexedDB on front desk workstations during an outage, as this will erase locally generated patient registration data.
- **DO NOT** turn away emergency walk-in patients during a branch network failure. Front desk staff must use offline token generation.

## Root Cause Follow-Up
- Review branch WAN/broadband failover to secondary LTE/4G backup router.
- Verify IndexedDB persistence policies across all front desk workstation browsers.
